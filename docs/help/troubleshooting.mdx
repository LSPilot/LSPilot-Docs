先确认「问题在哪一层」，再按症状往下查。LSPilot 的链路是：**LSPosed 注入 → 宿主进程初始化 → 插件加载 → Hook 执行**，AI 与工具则走**主进程 ↔ `:mcp` 进程**。

## 三个诊断入口

| 入口 | 看什么 |
| --- | --- |
| **首页激活卡** | 模块是否被框架识别（「已通过 Lsp 102 激活」/「未检测到 Xposed 框架」） |
| **应用详情 → 动态配置** | 与宿主进程的跨进程桥是否连接（已连接 / 未连接 / 连接中） |
| **应用详情 → 日志** | 插件是否加载成功、脚本是否抛错（`error/` 下的文件带完整堆栈） |

## 模块与注入

| 症状 | 排查 |
| --- | --- |
| 首页显示「未检测到 Xposed 框架」 | LSPosed 中是否启用模块；设备重启后 LSPosed 是否生效；模块是否因架构不匹配未安装成功 |
| 应用已启用但完全没反应 | LSPosed 作用域是否勾选该应用；是否强制停止并重启过；注入进程模式是否覆盖目标进程 |
| 多进程应用只有部分功能生效 | 注入进程改为「所有进程」 |
| 应用详情一直「未连接」 | 目标应用是否在运行；点「重连」；确认该应用确实被注入（切到目标应用再回来看状态） |

## 插件

| 症状 | 排查 |
| --- | --- |
| 插件列表里看不到 | 目录是否**同时**有 `main.java` 与 `info.prop`；是否放在 `<目标包名>` 分区下 |
| 显示「未知插件」 | `info.prop` 缺少 `name` |
| 日志里完全没有输出 | 插件开关是否打开；`main.java` 顶层是否有 `log(...)`；改完脚本是否重启过目标应用 |
| 出现 `error/` 文件 | 打开看堆栈，通常是语法错误、类名写错或方法签名不匹配 |
| Hook 没命中 | 先只写 `findClassOrNull` + 打印类名确认定位；再用 `hookMethodBefore` 只打一行日志确认命中；最后才改参数/返回值 |
| 改完脚本没变化 | `main.java` **不会热重载**，必须强制停止并重启目标应用 |
| 卸载插件后 Hook 还在 | 卸载不会自动解除 Hook，需要在 `onUnload()` 中 `unhook(...)` |
| 两个插件互相影响 | Hook 的 `id` 是全局键，不同插件用相同 id 会互相覆盖，请加插件前缀 |

## AI 与工具

| 症状 | 排查 |
| --- | --- |
| 工具没被调用 | 该工具所在**分组总开关**是否打开（分组默认关闭）；极简模式只保留 `run_command` |
| 提示工具进程不可用 | `:mcp` 进程可能被系统回收，重发一次消息即可自动重绑 |
| 第一次反编译很慢 | 属于懒加载，首次会建立索引，后续调用变快 |
| 输出被截断 | 超过 8000 字符会截断，让 AI 分页读取或先写入文件 |
| 上下文被工具定义占满 | 关闭不用的工具分组；或切到极简模式；在上下文用量面板看「工具定义」分项 |
| AI 说找不到类 | 让 AI 先用 `search_strings` / `find_class` 定位，再反编译确认 |

## MCP

| 症状 | 排查 |
| --- | --- |
| 连接失败 | 卡片上「查看错误」看原因；确认地址可达、请求头正确、服务端是否需要鉴权 |
| 连上了但没有工具 | 服务端是否实现了工具列表；下拉刷新重新发现 |
| 工具开关重启后丢失 | 正常情况下会按工具名保留，若确实丢失请重新连接一次 |
| MCP 插件工具用不了 | 插件是否启用（新建默认不启用）；`main.java` 是否用 `addTool` 声明成功 |

## 终端

| 症状 | 排查 |
| --- | --- |
| 首次打开很慢 | 正在下载 Ubuntu rootfs，取决于网络 |
| 提示需要 busybox | chroot 模式需要 busybox（Magisk / KernelSU 自带），或改用 proot 模式 |
| 命令找不到 | 容器内环境与应用内环境不同，需要在容器里 `apt install` |
| 想重置环境 | 设置 → 存储空间 → 终端环境（清除后下次启动会重新下载） |

## 界面

| 症状 | 排查 |
| --- | --- |
| 看不到检视 / 性能悬浮窗 | 是否授予悬浮窗权限；目标应用是否在前台 |
| 检视圈选没反应 | 悬浮窗的「穿透」开关是否打开（穿透开启时点击会传给应用本身） |
| 性能面板没有数据 | 该项目的「实时性能面板」是否打开；指标是否被勾选 |
| 页面显示异常 | 设置 → 外观里把页面缩放调回 100%；关闭模糊 / 液态玻璃试试 |

## 还是不行？

把这三样一起带上再反馈，定位会快很多：

1. **环境信息**：设备型号、Android 版本、LSPosed 版本、LSPilot 版本；
2. **目标应用**：名称、版本号、包名；
3. **日志**：插件 `error/` 目录下的错误文件，或 logcat 中 tag 为 `LSPilot` 的输出。

反馈渠道见[常见问题](/help/faq)页尾。
