用五分钟跑通一次完整流程：选应用 → 提问 → AI 定位 → 生成插件 → 注入验证。

## 前置准备

1. 已完成 [安装与激活](/start/installation)。
2. 已授予「所有文件访问权限」与「读取应用列表」。
3. 已配置至少一个 AI 供应商（**设置 → 通用 → 供应商**，填入 API 密钥并获取模型列表）。

## 步骤

<Steps>
  <Step>**添加目标应用**：进入**项目 → 应用**，找到目标应用并打开右侧开关；确认 LSPosed 的作用域中也勾选了它。首次启用后强制停止并重新打开目标应用。</Step>

  <Step>**进入 AI 对话**：在应用详情页进入「分析」，或直接进入 AI 对话并选择当前项目。输入框上方可以切换模型、对话模式与推理强度。</Step>

  <Step>**用一句话描述需求**，例如「反编译这个应用，找出登录请求是在哪里发出的，然后给我一个打印请求参数与调用栈的插件」。</Step>

  <Step>**观察 AI 的工作过程**：AI 会在对话中展开「工作过程」卡片，逐条显示调用了哪些工具、参数是什么、返回了什么。常见顺序是 `search_strings` → `find_usage` → `decompile_class` → `create_plugin`。</Step>

  <Step>**检查生成的插件**：AI 生成插件后会在对话中给出插件路径。进入**应用详情 → 插件**可以看到它，点进去即可在代码编辑器中查看与修改 `main.java`。</Step>

  <Step>**启用并验证**：打开插件开关（运行时即时生效），然后操作目标应用触发对应逻辑，观察 Toast 提示与日志。日志在**应用详情 → 日志**中查看。</Step>
</Steps>

## 一个最小示例

如果只想手动跑通一次，可以创建一个插件，内容如下：

```java
// main.java
log("插件已加载，宿主版本:", hostVerName, "(", hostVerCode, ")");

Class clazz = findClassOrNull("com.example.target.MainActivity", hostLoader);
if (clazz == null) {
    log("没找到目标类，请先确认类名");
} else {
    hookMethodAfter(clazz, "onCreate", param -> {
        toast("MainActivity 已创建");
        log("onCreate 被调用，实例:", param.thisObject);
    });
}
```

<Callout type="warn">
  修改 `main.java` 的内容**不会**热重载，需要强制停止并重启目标应用。只有切换插件开关可以在运行时即时生效。
</Callout>

## 让 AI 更准的技巧

- **说清目标**：是想知道逻辑在哪、追踪调用链、打印参数，还是修改返回值。
- **给出已知信息**：字符串常量、界面文案、类名片段、报错信息都能显著提高命中率。
- **先定位再动手**：让 AI 先用 DexKit 搜索与反编译确认，再让它写插件。
- **分步迭代**：一次只让 AI 解决一个问题，验证通过后再继续。
- **让它解释**：要求 AI 说明「为什么是这个类/方法」，方便你判断结论是否可靠。
