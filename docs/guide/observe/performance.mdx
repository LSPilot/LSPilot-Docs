性能观测回答两个问题：应用到底掉不掉帧，以及掉帧时是哪个方法在拖后腿。

## 性能悬浮窗

入口：**设置 → 关于 → 实验性功能 → 性能悬浮窗**（实验模式的进入方式见[外观与界面](/guide/custom/appearance)）。也可以在应用详情页的**动态配置**中为单个项目打开「实时性能面板」。

开启后会在屏幕上实时显示目标应用的运行指标，可自由拖动位置，不需要任何系统权限。

### 可显示的指标

| 指标 | 说明 |
| --- | --- |
| 实时帧率 | 基于 Choreographer 采样 |
| 近期最低帧率 | 1% low（LOW） |
| 进程 CPU 占用率 | 目标应用进程 |
| 进程内存占用 | 目标应用进程 |
| 总内存 | 设备总内存 |
| 电量百分比 / 电池温度 | 设备状态 |
| 主板温度 | 设备温度 |

### 外观与行为

| 配置项 | 说明 |
| --- | --- |
| 显示指标 | 逐项勾选要展示的指标 |
| 指标排列方向 | 水平 / 垂直 |
| 样式 | 条形 / 文本 / 实时折线等 |
| 位置 | 左上 / 上中 / 右上 / 左中 / 中间 / 右中 / 左下 / 下中 / 右下 |
| 强调色 | 悬浮窗主题强调色 |
| 背景不透明度 | 卡片背景透明度 |
| 文字大小 | 悬浮窗内文字尺寸 |
| 刷新间隔 | 指标轮询周期（0.5s / 1s / 2s） |
| 预警阈值 / 危险阈值 | 超过预警显示黄色，超过危险显示红色 |
| 持续特效 | 保持动态效果 |

## 卡顿定位

<Callout type="warn">
  卡顿定位的界面入口在当前版本中被暂时隐藏（功能与数据采集仍在代码中保留）。下面的说明用于描述其能力与指标口径。
</Callout>

卡顿定位监控目标应用主线程：**主线程连续忙碌超过 50ms 即记为一次卡顿并自动抓取堆栈**。

界面按出现次数排序展示热点方法，最靠前的方法最可能是卡顿元凶。可以看到：

- 卡顿次数、最久一次耗时、热点方法数量；
- 每个热点方法的出现次数与累计耗时；
- 主线程占用率。

可用操作：**清空**当前记录，或**导出**卡顿数据便于进一步分析。

<Callout type="info">
  如果提示「暂未捕获到卡顿」，说明目标应用当前没有出现超过阈值的主线程阻塞。可以去引发卡顿的界面操作一下（例如进入主页、快速滑动列表），再回来查看。
</Callout>

## 使用建议

- 先用性能悬浮窗确认「到底掉不掉帧、掉在什么时候」；
- 再用卡顿定位找出热点方法；
- 最后用 UI 检视与反编译确认这段代码在做什么，决定是否需要 Hook 或优化。
