MCP 拓展页有三个标签，分别对应三类完全不同的东西，先分清楚再配置。

## 三个标签

**设置 → 功能拓展 → MCP 拓展**是一个三标签聚合页：

| 标签 | 是什么 | 作用 |
| --- | --- | --- |
| 本地 | 远程 MCP **客户端** | 连接外部 MCP 服务器，自动发现并注入它们的工具 |
| 内置 | LSPilot 自带的 FunctionCall 工具 | 查看、开关与试运行内置工具（与 MCP 协议无关，只是放在同一页） |
| 插件 | 用 BeanShell 脚本声明工具 | 把常用分析流程固化成 AI 可调用的本地工具 |

<Callout type="info">
  「插件」标签里的 MCP 插件与[插件开发](/plugin/app/introduction)里的**项目插件不是一回事**：项目插件注入目标应用进程做 Hook；MCP 插件运行在 LSPilot 自己的进程里，只负责向 AI 提供工具。
</Callout>

## 工具是怎么到 AI 手里的

每次发送消息前，LSPilot 会把三部分工具定义合并后注入请求：

1. **内置工具**：按分组总开关与逐项开关过滤；
2. **外部 MCP 工具**：来自已启用服务器上已发现且已开启的工具；
3. **MCP 插件工具**：来自已启用插件中未被禁用的工具。

AI 返回工具调用后，LSPilot 按函数名前缀路由：

| 前缀 | 来源 | 执行位置 |
| --- | --- | --- |
| 无前缀 | 内置工具 | 独立 `:mcp` 进程 |
| `mcp__<服务器>__<工具>` | 外部 MCP 服务器 | 独立 `:mcp` 进程 |
| `plugin__<插件目录>__<工具>` | MCP 插件 | 主进程中的 BeanShell 解释器 |

函数名会被自动规范化：中文会转写为拼音，非法字符压成下划线，因此「工具名」可以用中文书写，AI 侧看到的是合法标识符。

## 为什么 MCP 客户端跑在独立进程

LSPilot 把内置工具与 MCP 客户端放在独立的 `:mcp` 进程里，主进程只通过 Binder 调用它。这样做的好处：

- **内存隔离**：DexKit 的全量索引等重型内存开销不计入主进程堆；
- **崩溃隔离**：工具或 MCP 连接崩溃只影响 `:mcp` 进程，界面不受影响，下次调用会自动重新绑定。

## 极简模式下的行为

对话模式选择**极简模式**时：

- 外部 MCP 工具与 MCP 插件工具**完全不注入**；
- 内置工具只保留终端工具 `run_command`；
- 你在拓展页保存的开关不会被修改，切回普通模式即恢复。

详见 [对话 · 对话模式](/guide/ai/chat)。
